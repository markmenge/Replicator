# OpenSCAD CAD Modeling Skill

## Purpose

Use this skill when generating, modifying, reviewing, or iterating on OpenSCAD
models.

The primary objective is not merely to produce valid OpenSCAD syntax. The
objective is to produce CAD that is:

- Geometrically appropriate for the object.
- Parametric and easy to modify.
- Mechanically coherent.
- Manufacturable or printable when required.
- Easy to inspect and debug.
- Stable under AI iteration.
- Built from the correct geometric abstraction.
- Readable enough that another engineer can understand the design intent.

The most important rule is:

> Do not start by writing geometry. First determine the correct construction
> method for the object.

A good OpenSCAD model is usually the result of choosing the correct modeling
grammar.

Examples:

- A rook is a revolved side profile plus crown cuts.
- A gear is an involute gear generated by a proven library.
- A bracket is usually an extruded sketch with holes and ribs.
- A bent tube is a profile swept along a path.
- A gearbox is a shaft and gear layout first, with a housing built around it.
- A detailed face or animal is usually better modeled as a mesh in a sculpting
  tool and imported into OpenSCAD for mechanical additions.

---

# 1. Required Reasoning Before Modeling

Before generating OpenSCAD code, determine the following.

## 1.1 Intended use

Classify the model as one or more of:

- Visual concept.
- 3D-printable prototype.
- Functional mechanical part.
- Assembly component.
- CNC or machined component.
- Mold or fixture.
- Reference geometry.
- Decorative object.
- Kinematic mechanism.
- Parametric generator.

The intended use determines how much accuracy, clearance, structure, and
validation are required.

## 1.2 Dominant geometry

Ask these questions in order:

1. Is the object symmetric around an axis?
   - Prefer `rotate_extrude()` or a revolved profile.

2. Does the object have a constant cross-section?
   - Prefer `linear_extrude()`.

3. Does a cross-section follow a path?
   - Prefer a sweep.

4. Does the cross-section change along its length?
   - Prefer a loft or skin between sections.

5. Is the object mainly a hollow shell?
   - Build the outer solid, then subtract the interior.

6. Is the object made from repeated elements?
   - Build one element, then use an array or repeated transforms.

7. Is the geometry defined by a standard?
   - Use a trusted library.

8. Is the object defined by joint locations and motion?
   - Build a kinematic skeleton first.

9. Is the object highly organic?
   - Consider an external mesh or sculpting tool.

10. Is the part primarily defined by interfaces to other components?
    - Model those interfaces first.

## 1.3 Manufacturing analogy

Whenever possible, model the object in the same conceptual order in which it
would be manufactured.

Examples:

- Lathe part:
  1. Turn the body.
  2. Drill the bore.
  3. Cut slots.
  4. Add secondary features.

- Machined bracket:
  1. Start with stock.
  2. Remove pockets.
  3. Drill holes.
  4. Add chamfers.

- Enclosure:
  1. Create outer body.
  2. Hollow the body.
  3. Add bosses.
  4. Cut ports.
  5. Add lid features.

- Mold:
  1. Create mold block.
  2. Subtract the master.
  3. Add parting features.
  4. Add vents and gates.

A CAD construction that resembles the manufacturing process is usually easier
to understand and maintain.

# 2. Construction Method Selection Table

| Object type | Construction method | Description |
|---|---|---|
| Rook, pawn, bishop body | Revolved profile | Define a 2D `[radius, height]` profile and use `rotate_extrude()`. Add non-axisymmetric features afterward. |
| Vase, bowl, bottle | Revolved profile | Use when the shape is rotationally symmetric. |
| Shaft, spacer, washer | Cylinders or revolved profile | Use a revolved profile for shoulders, grooves, tapers, and bearing seats. |
| Pulley | Revolved profile plus cuts | Revolve the body, then subtract bore, keyway, and grooves. |
| Wheel or tire | Revolved profile plus repeated features | Revolve the main body, then add or subtract tread around the circumference. |
| Knob | Revolved body plus grip features | Revolve the body, then add flutes, knurl-like geometry, finger recesses, or pointer marks. |
| Gear | Proven involute gear generator | Prefer BOSL2 or another trusted gear library. Do not approximate functional teeth with rectangles. |
| Sprocket | Standard tooth generator | Generate tooth geometry from roller diameter, pitch, and tooth count. |
| Timing pulley | Belt-specific generator | Use the correct belt tooth standard. |
| Flat mounting plate | 2D sketch plus `linear_extrude()` | Build outline and holes in 2D, then extrude. |
| L bracket | Extruded plates plus ribs | Build primary plates, subtract holes, then add reinforcement. |
| Motor mount | Interface-first extrusion | Start with shaft center, motor face, bolt pattern, and keep-out volume. |
| Bearing holder | Interface-first solid | Model bearing pocket, shaft axis, shoulder, fit, and installation clearance first. |
| Electronics enclosure | Outer solid minus cavity | Add bosses, ports, vents, clips, and lid features afterward. |
| Gearbox housing | Mechanism-first shell | Place gears, shafts, bearings, and fasteners before designing the housing. |
| Project box lid | Extruded outline plus lip | Add locating lip, gasket channel, screws, or clips. |
| Straight tube | Outer solid minus inner solid | Parameterize wall thickness. |
| Bent pipe | Sweep | Sweep a circular profile along a path. |
| Cable guide | Sweep | Sweep a custom profile along a controlled path. |
| Structural frame | Cross-section along centerlines | Define frame skeleton first. |
| Duct or nozzle | Loft between sections | Transition between changing cross-sections. |
| Funnel | Revolve or loft | Revolve if round; loft if transitioning between different shapes. |
| Airfoil or wing | Lofted airfoil sections | Control chord, twist, sweep, and thickness parametrically. |
| Propeller or fan blade | Lofted blade sections | Use multiple blade sections with changing pitch and chord. |
| Cam | Mathematical 2D profile plus extrusion | Generate outline from motion law or polar function. |
| Linkage arm | Pivot skeleton plus extrusion | Locate pivot centers first, then build body around them. |
| Lever | Interface-first extrusion | Define pivot, force point, load point, and motion envelope first. |
| Robot linkage | Kinematic skeleton | Define joint axes and link lengths before final bodies. |
| Clock mechanism | Library gears plus shaft layout | Determine ratios and center distances first. |
| Belt mechanism | Pulley centers plus belt path | Verify wrap and clearance before mounts and guards. |
| Chain mechanism | Sprocket centers plus chain path | Use real pitch and roller dimensions. |
| Sheet metal bracket | Flat pattern plus bend abstraction | OpenSCAD can represent folded geometry but is not a full sheet-metal system. |
| Cabinet or furniture | Panel construction | Model each board separately with thickness and joinery. |
| Architectural walls | 2D plan plus extrusion | Add openings and roof elements as separate modules. |
| Heat sink | Base plus repeated fins | Build one fin and repeat it. |
| Honeycomb panel | Repeated cell pattern plus trim | Generate cells, then intersect with panel boundary. |
| Lattice | Repeated cells or struts | Build one unit and repeat. |
| Vent grille | 2D repeated pattern plus extrusion | Subtract repeated openings from a panel. |
| Fluid manifold | Solid minus channel network | Subtract cylindrical or swept passages. |
| Mold | Mold block minus master | Add draft, vents, gates, keys, and parting features as required. |
| Snap fit | Cantilever beam geometry | Model root, hook, lead-in, thickness, and allowable deflection. |
| Clip or clamp | Flexible path plus gripping features | Start from retained-object geometry and required deflection. |
| Living hinge | Thin web plus relief pattern | Material and print orientation are critical. |
| Threaded part | Standard thread generator | Use trusted thread geometry and explicit fit allowance. |
| Text or logo | `text()` or imported SVG plus extrusion | Add or subtract from the body. |
| Terrain | `surface()` from height map | Use image or elevation data. |
| Relief artwork | Height map or layered contours | Better for shallow relief than full sculpture. |
| Stylized animal | Primitive composition, hull, loft | Suitable for simplified shapes. |
| Detailed statue or face | Imported mesh | Use Blender, ZBrush, or similar for sculpting. |
| Chess knight | Extruded silhouette or imported mesh | Not rotationally symmetric. |
| Standard screw, bearing, motor | Reusable reference module | Use accurate reference geometry to drive interfaces. |
| Multi-part assembly | Modules with common datums | Give each part a defined origin and assembly transform. |

# 3. Geometry Hierarchy

Build models in this order whenever practical.

## 3.1 Reference geometry

Reference geometry does not become part of the final printed object.

Examples:

- Shaft axes.
- Bearing envelopes.
- Motor envelope.
- PCB outline.
- Gear pitch circles.
- Pivot locations.
- Belt or chain path.
- Motion envelope.
- Tool-access volume.
- Fastener axes.
- Connector keep-out volume.

Use OpenSCAD preview modifiers when useful:

```scad
%reference_motor();
%reference_bearing();
#critical_clearance_volume();
```

## 3.2 Primary mass

Create only the main body.

Examples:

- Revolved blank.
- Extruded plate.
- Housing block.
- Swept tube.
- Lofted shell.
- Structural frame.

Do not add decorative details yet.

## 3.3 Functional features

Add:

- Bores.
- Pockets.
- Bearing seats.
- Fastener holes.
- Keyways.
- Slots.
- Mounting bosses.
- Cable channels.
- Gear teeth.
- Snap features.
- Crown cuts.
- Retaining features.

## 3.4 Cosmetic features

Add last:

- Fillets.
- Chamfers.
- Text.
- Logos.
- Surface patterns.
- Decorative grooves.
- Knurl-like geometry.
- Accent rings.

Cosmetic geometry should never obscure basic mechanical errors.

# 4. Parametric Design Rules

## 4.1 Put important parameters near the top

Example:

```scad
// Functional dimensions
shaft_d = 5.0;
bearing_od = 16.0;
bearing_w = 5.0;

// Manufacturing allowances
shaft_radial_clearance = 0.25;
bearing_fit_adjustment = -0.10;

// Structural dimensions
wall_t = 3.0;
floor_t = 4.0;
rib_t = 3.0;

// Cosmetic dimensions
edge_rounding = 1.5;
label_depth = 0.5;
```

## 4.2 Separate design categories

Keep these conceptually distinct:

- Functional dimensions.
- Standard component dimensions.
- Manufacturing allowances.
- Structural dimensions.
- Cosmetic dimensions.
- Rendering quality settings.

## 4.3 Derive dimensions instead of duplicating them

Bad:

```scad
shaft_d = 5;
shaft_hole_d = 5.5;
```

Better:

```scad
shaft_d = 5;
shaft_radial_clearance = 0.25;
shaft_hole_d = shaft_d + 2 * shaft_radial_clearance;
```

Derived dimensions reduce inconsistency.

## 4.4 Avoid magic numbers

Bad:

```scad
translate([41.7, -2.3, 19.8])
```

Better:

```scad
output_shaft_x = 42.0;
shaft_axis_z = 20.0;

translate([output_shaft_x, 0, shaft_axis_z])
```

Every important location should have a reason.

---

# 5. Coordinate Systems and Datums

Choose a coordinate convention and preserve it.

Recommended default:

- X = left/right.
- Y = front/back.
- Z = up/down.
- Bottom surface at `z = 0`.
- Primary assembly datum near the origin.
- Shaft axes placed on simple coordinates when possible.

For rotational parts:

- Put the main rotation axis on Z.
- Put the bottom at Z = 0.
- Use `[radius, height]` profile points.

For assemblies:

- Define master datums.
- Define part-local coordinate systems.
- Place parts using named transforms.

Do not make each part use an unrelated origin.

---

# 6. Rotational and Lathe-Style Modeling

Rotationally symmetric objects should normally be modeled using a side profile.

Example:

```scad
profile = [
    [0.0, 0.0],
    [18.0, 0.0],
    [19.0, 2.0],
    [17.0, 5.0],
    [12.0, 12.0],
    [10.0, 30.0],
    [13.0, 42.0],
    [13.0, 50.0],
    [0.0, 50.0]
];

rotate_extrude($fn = 160)
    polygon(profile);
```

Rules:

- Keep all profile radii nonnegative.
- Make the profile a closed polygon.
- Use more points where curvature changes quickly.
- Use fewer points on nearly straight sections.
- Keep the profile array separate from the final solid.
- Treat the lathed form as the manufacturing blank.
- Add slots, holes, flats, and asymmetric features afterward.

For AI iteration, modify profile points instead of replacing the entire model.

---

# 7. Extrusion-Based Modeling

Use `linear_extrude()` when geometry is primarily defined in a 2D plane and has
constant thickness.

Typical parts:

- Plates.
- Brackets.
- Signs.
- Gaskets.
- Linkage arms.
- Flat structural parts.
- Vents.
- Logos.
- Stylized silhouettes.

Preferred workflow:

1. Define 2D outline.
2. Define 2D holes and cutouts.
3. Use `difference()` in 2D where possible.
4. Extrude the final 2D result.
5. Add truly 3D features afterward.

This is usually simpler than performing every subtraction in 3D.

---

# 8. Sweep-Based Modeling

Use a sweep when a profile follows a path.

Examples:

- Bent tube.
- Wire guide.
- Cable conduit.
- Handrail.
- Curved structural member.
- Hose.
- Curved slot.

Prefer BOSL2 sweep functions when practical.

Modeling strategy:

1. Define the path separately.
2. Define the cross-section separately.
3. Sweep the cross-section along the path.
4. Validate bend radius and self-intersection.
5. Add end features separately.

Do not approximate a smooth curved tube by manually chaining many cylinders
unless the application is intentionally low fidelity.

---

# 9. Loft and Skin Modeling

Use lofting when cross-sections change along an axis or path.

Examples:

- Duct transition.
- Nozzle.
- Wing.
- Propeller blade.
- Ergonomic grip.
- Organic mechanical housing.

Strategy:

1. Define cross-sections.
2. Place them at explicit stations.
3. Ensure consistent point ordering.
4. Use BOSL2 `skin()` or another proven loft method.
5. Validate that sections do not fold or self-intersect.

For AI-generated lofts, keep section generation and section placement separate.

---

# 10. Standard Mechanical Geometry

Do not regenerate difficult standard geometry from scratch when a trusted
library exists.

Prefer libraries for:

- Involute gears.
- Bevel gears.
- Worm gears.
- Threads.
- Fasteners.
- Bearings.
- Springs.
- Timing pulleys.
- Standard profiles.
- Sweep and loft operations.

BOSL2 should generally be preferred over hand-built equivalents when it already
provides the needed operation.

A library is not merely a shortcut. It contains geometric expertise.

---

# 11. Interface-First Mechanical Design

For functional CAD, interfaces are more important than exterior appearance.

## 11.1 Motor mount

Model first:

- Shaft center.
- Mounting face.
- Bolt pattern.
- Motor body envelope.
- Connector clearance.
- Output alignment.

Then build the bracket around those constraints.

## 11.2 Bearing support

Model first:

- Shaft axis.
- Bearing OD.
- Bearing width.
- Fit allowance.
- Retaining shoulder.
- Insertion direction.
- Tool access.

Then build the support body.

## 11.3 Electronics enclosure

Model first:

- PCB outline.
- Mounting holes.
- Connector positions.
- Maximum component heights.
- Cable bend volumes.
- Button and display locations.

Then build the enclosure.

## 11.4 Gearbox

Model first:

- Shaft axes.
- Gear pitch diameters.
- Center distances.
- Bearing positions.
- Fastener locations.
- Gear axial spacing.
- Lubrication or clearance volume if applicable.

Then build the housing.

---

# 12. Clearances and Fits

Never assume nominal dimensions will produce the desired fit.

Represent fit intent explicitly.

Example:

```scad
shaft_d = 5.0;
shaft_radial_clearance = 0.25;

shaft_hole_d = shaft_d + 2 * shaft_radial_clearance;
```

Maintain separate values for:

- Sliding fit.
- Rotating fit.
- Press fit.
- Screw clearance.
- Printed-in-place gap.
- Assembly gap.
- Adhesive gap.
- Bearing pocket adjustment.

Do not use one global "clearance" parameter for everything.

Clearance depends on:

- Printer.
- Material.
- Orientation.
- Feature size.
- Hole direction.
- Nozzle size.
- Post-processing.
- Desired fit.

For critical fits, recommend a small test coupon before printing the full part.

# 13. Boolean Geometry Rules

Boolean robustness is essential.

## 13.1 Avoid coincident faces

Bad:

```scad
difference() {
    cube([20, 20, 10]);
    translate([10, 10, 0])
        cylinder(d = 5, h = 10);
}
```

Better:

```scad
eps = 0.02;

difference() {
    cube([20, 20, 10]);

    translate([10, 10, -eps])
        cylinder(d = 5, h = 10 + 2 * eps);
}
```

Extend cutting solids slightly beyond the target surface.

## 13.2 Avoid zero-thickness connections

Two solids touching only at an edge or point are risky.

Give connected features real overlap.

## 13.3 Keep subtraction modules understandable

Prefer:

```scad
module mounting_holes() {
    // ...
}

module clearance_cuts() {
    // ...
}

difference() {
    main_body();
    mounting_holes();
    clearance_cuts();
}
```

rather than one enormous nested Boolean expression.

# 14. Modules and Code Architecture

Modules should represent meaningful geometric concepts.

Good module names:

- `turned_body()`
- `bearing_pocket()`
- `motor_mount_holes()`
- `cover()`
- `gear_stage_1()`
- `crown_slots()`
- `pcb_reference()`
- `assembly()`
- `exploded_view()`

Avoid modules that exist only to hide random geometry with no design meaning.

Recommended structure:

```scad
// Parameters
// Constants
// Derived dimensions
// Validation
// Reference geometry
// Primitive helper modules
// Component modules
// Part modules
// Assembly modules
// Display selection
```

---

# 15. Assertions and Diagnostics

Use `assert()` to detect impossible parameter combinations.

Example:

```scad
assert(shaft_d > 0);
assert(bearing_od > shaft_d);
assert(wall_t >= 2.0);
assert(cavity_radius < outer_radius - wall_t);
```

Use `echo()` for important derived values:

```scad
echo("Output shaft X:", output_shaft_x);
echo("Gear ratio:", gear_ratio);
echo("Minimum wall thickness:", wall_t);
```

AI-generated CAD should validate its own assumptions whenever possible.

---

# 16. Rendering Resolution

Avoid extremely large global `$fn` values.

Prefer reasonable defaults:

```scad
$fn = 48;
```

Then increase resolution only where needed:

```scad
cylinder(d = 5, h = 10, $fn = 32);
cylinder(d = 80, h = 10, $fn = 120);
```

For final display models, higher resolution is acceptable.

For iterative AI work, keep previews fast.

A slow model reduces the number of useful design iterations.

---

# 17. Assemblies

Treat every printable or manufactured component as a separate module.

Example:

```scad
module base() {
    // ...
}

module cover() {
    // ...
}

module assembly() {
    base();

    translate([0, 0, cover_z])
        cover();
}
```

Useful display modes:

```scad
mode = "assembly";

if (mode == "base")
    base();

if (mode == "cover")
    cover();

if (mode == "assembly")
    assembly();

if (mode == "exploded")
    exploded_assembly();
```

Recommended assembly views:

- Individual part.
- Full assembly.
- Exploded assembly.
- Section view.
- Reference geometry.
- Motion or animation view.

---

# 18. Kinematic Models

For mechanisms, model motion before cosmetic bodies.

Use this order:

1. Define joint axes.
2. Define link lengths.
3. Define degrees of freedom.
4. Create a kinematic skeleton.
5. Validate motion.
6. Add component envelopes.
7. Add structural bodies.
8. Add cosmetic geometry.

For gears:

1. Compute ratios.
2. Choose tooth counts.
3. Compute pitch diameters.
4. Place shaft centers.
5. Generate gears.
6. Validate meshing.
7. Add bearings.
8. Add housing.

For linkages:

1. Define pivot locations.
2. Validate motion range.
3. Detect interference.
4. Add link bodies.

Do not design a beautiful housing around a mechanism that has not yet been
validated.

---

# 19. Design for 3D Printing

When the model will be printed, evaluate:

- Minimum wall thickness.
- Hole orientation.
- Overhangs.
- Bridging.
- Support removal.
- Layer-direction strength.
- Part orientation.
- Elephant-foot sensitivity.
- Screw-hole behavior.
- Heat-set insert clearances.
- Bearing insertion.
- Snap-fit direction.
- Print-in-place clearances.

When practical:

- Orient tensile loads across multiple layers.
- Avoid inaccessible support material.
- Add chamfers to insertion edges.
- Add relief around press-fit entries.
- Flatten the intended print surface.
- Use test coupons for uncertain fits.

---

# 20. Design for Machining

When the part is intended for machining, consider:

- Tool access.
- Cutter diameter.
- Inside corner radius.
- Workholding.
- Setup count.
- Bore depth.
- Drill access.
- Standard stock dimensions.
- Tolerance-critical surfaces.
- Datum surfaces.

OpenSCAD can describe machined geometry well, but the model should respect real
tool constraints.

# 21. AI Image-to-CAD Workflow

When a visual reference is available, do not immediately attempt to recreate
the entire 3D object from pixels.

First determine what information can be extracted reliably.

Possible representations:

- Side silhouette.
- Axial profile.
- Centerline.
- Cross-sections.
- Landmark points.
- Bounding dimensions.
- Repeated pattern.
- Symmetry axes.
- Feature ratios.

For a rotational object such as a rook:

1. Find a clean side view.
2. Identify the axis of rotation.
3. Extract the outer silhouette.
4. Convert the silhouette to `[radius, height]` points.
5. Revolve the profile.
6. Add non-axisymmetric cuts separately.
7. Render an orthographic side view.
8. Compare the result against the reference.
9. Adjust profile points only.

This is much more reliable than repeatedly generating arbitrary primitive
combinations.

# 22. AI Iteration Strategy

A weak loop is:

```text
Generate model.
Render.
Make it better.
Repeat.
```

Avoid this.

A strong loop is:

1. Classify the object.
2. Choose the construction method.
3. Define stable parameters.
4. Define interfaces.
5. Generate stable model architecture.
6. Render fixed views.
7. Critique specific measurable features.
8. Change only relevant parameters or modules.
9. Render again.
10. Stop when acceptance criteria are met.

The AI should not rewrite the entire model on every iteration.

---

# 23. Structured Critique

Critiques should be explicit.

Bad critique:

```text
The rook still looks a little wrong.
```

Better:

```json
{
  "base_radius": "increase by 1.5 mm",
  "stem_mid_radius": "decrease by 0.8 mm",
  "collar_height": "decrease by 1.0 mm",
  "crown_radius": "increase by 0.5 mm",
  "slot_depth": "decrease by 1.0 mm"
}
```

For mechanical models, critique:

- Dimensional correctness.
- Fit.
- Alignment.
- Interference.
- Manufacturability.
- Tool access.
- Printability.
- Structural weakness.

For aesthetic models, critique:

- Proportions.
- Silhouette.
- Curvature.
- Feature spacing.
- Symmetry.
- Relative scale.

---

# 24. Fixed Camera Views for Iteration

When using image feedback, use the same camera and scale every time.

Recommended views:

- Front orthographic.
- Side orthographic.
- Top orthographic.
- Isometric.
- Section.
- Exploded assembly when applicable.

Fixed camera geometry makes visual comparison meaningful.

Do not compare renders made from arbitrary viewpoints.

---

# 25. Generator and Critic Separation

Use separate conceptual roles.

## Generator

The generator:

- Writes or modifies OpenSCAD.
- Changes parameters.
- Implements requested geometry.
- Preserves stable architecture.

## Critic

The critic:

- Evaluates renders.
- Checks measurements.
- Identifies defects.
- Recommends parameter changes.
- Does not immediately rewrite the model.

This reduces self-reinforcing errors.

---

# 26. Freeze Successful Geometry

Once a subsystem is correct, mark it as stable.

Example:

```text
gear geometry: frozen
shaft spacing: frozen
bearing pockets: frozen
housing exterior: editable
cover attachment: editable
```

An iteration intended to improve one area should not modify unrelated stable
geometry.

This is especially important for AI-driven iterative CAD.

---

# 27. Reference Components

Use purchased components as reference geometry.

Examples:

- Bearings.
- Motors.
- PCBs.
- Connectors.
- Screws.
- Nuts.
- Washers.
- Displays.
- Fans.
- Switches.

Reference components should normally:

- Have accurate critical dimensions.
- Use a consistent origin.
- Be easy to display with `%`.
- Drive mating geometry.
- Not become part of the exported printable object.

# 28. Choosing Between OpenSCAD and Other Tools

OpenSCAD is especially strong for:

- Parametric mechanical parts.
- Fixtures.
- Brackets.
- Enclosures.
- Repeated structures.
- Gears.
- Mechanisms.
- Procedural geometry.
- Profile-driven objects.
- Dimension-driven assemblies.
- 3D-printable hardware.

OpenSCAD is weaker for:

- Human faces.
- Animals.
- Cloth.
- Highly organic surfaces.
- Freeform sculpture.
- Direct interactive surface editing.
- Traditional constraint-based engineering drawings.

Recommended hybrid workflow:

```text
Organic geometry tool
        |
        v
Imported STL or mesh
        |
        v
OpenSCAD adds mechanical interfaces
        |
        v
Mounts, holes, bases, sockets, fixtures
```

Use the best tool for each geometry class.

# 29. Common Failure Modes

## 29.1 Primitive stacking

Symptom:

- Cylinders and cubes are stacked until an object is vaguely recognizable.

Why it fails:

- Poor curvature.
- Poor proportion control.
- Difficult iteration.
- No meaningful design representation.

Fix:

- Find the correct profile, sweep, loft, or library representation.

## 29.2 Rewriting the whole file every iteration

Symptom:

- Previously correct geometry changes unexpectedly.

Fix:

- Freeze architecture.
- Modify parameters.
- Change one subsystem at a time.

## 29.3 Designing the enclosure before the mechanism

Symptom:

- Bearings, screws, or gears do not fit.

Fix:

- Build interfaces and mechanism first.

## 29.4 Magic-number placement

Symptom:

- Many unexplained translations and rotations.

Fix:

- Use named datums and derived positions.

## 29.5 Exact nominal fits

Symptom:

- Printed shafts do not fit holes.

Fix:

- Model fit intent explicitly.

## 29.6 Hand-built standard geometry

Symptom:

- Poor gear teeth, threads, or timing pulley profiles.

Fix:

- Use a trusted library.

## 29.7 Excessive rendering detail

Symptom:

- Iteration becomes slow.

Fix:

- Use moderate preview resolution and increase quality only for final output.

## 29.8 Aesthetic iteration with no measurable objective

Symptom:

- Shape oscillates from one iteration to the next.

Fix:

- Use fixed camera views and structured parameter critiques.

## 29.9 Modeling an organic object in OpenSCAD

Symptom:

- The result looks robotic or blocky.

Fix:

- Use a sculpting or mesh tool, then import into OpenSCAD for mechanical work.

# 30. Recommended AI Modeling Procedure

When asked to generate a model, follow this procedure.

## Step 1: Restate the design objective internally

Determine:

- What is being modeled?
- What must it do?
- What are the critical dimensions?
- Is it visual or functional?

## Step 2: Classify the geometry

Choose one or more:

- Revolve.
- Extrude.
- Sweep.
- Loft.
- Shell.
- Array.
- Library primitive.
- Kinematic skeleton.
- Imported mesh.

## Step 3: Identify interfaces

List:

- Mounting points.
- Axes.
- Bores.
- Bearings.
- Fasteners.
- Connectors.
- Contact surfaces.
- Moving envelopes.

## Step 4: Establish coordinate system

Define origin and axes.

## Step 5: Define parameters

Separate functional, manufacturing, structural, and cosmetic parameters.

## Step 6: Create reference geometry

Show components and keep-out regions.

## Step 7: Build primary mass

Use the selected construction method.

## Step 8: Add functional features

Add holes, pockets, slots, seats, and attachment features.

## Step 9: Add validation

Use assertions and diagnostic echoes.

## Step 10: Add cosmetic geometry

Only after the part is mechanically valid.

## Step 11: Create inspection modes

Provide useful views or display modes.

## Step 12: Iterate parametrically

Modify parameters rather than rewriting architecture.

# 31. Quality Checklist

Before considering an OpenSCAD model complete, check the following.

## Geometry

- [ ] Correct construction method was selected.
- [ ] Geometry is manifold or expected to render as a valid solid.
- [ ] No unintended zero-thickness connections.
- [ ] Boolean cuts extend through the target volume.
- [ ] No suspicious coincident faces.
- [ ] Curves have appropriate resolution.

## Parameters

- [ ] Important dimensions are named.
- [ ] Derived dimensions are calculated rather than duplicated.
- [ ] No unexplained magic numbers control critical geometry.
- [ ] Units are consistent.

## Mechanical design

- [ ] Interfaces are modeled accurately.
- [ ] Fits and clearances are explicit.
- [ ] Moving parts have clearance.
- [ ] Fasteners are accessible.
- [ ] Components can be assembled.
- [ ] Components can be removed if serviceability matters.

## Manufacturing

- [ ] Minimum wall thickness is acceptable.
- [ ] Print orientation or machining strategy is reasonable.
- [ ] Tool or support access is possible.
- [ ] Standard component dimensions are realistic.

## AI iteration

- [ ] Stable modules are preserved.
- [ ] Parameters control the features likely to change.
- [ ] Render viewpoints are consistent.
- [ ] Critiques are measurable.
- [ ] Only relevant geometry changes per iteration.

## Readability

- [ ] Modules have meaningful names.
- [ ] Coordinate system is understandable.
- [ ] Comments explain design intent rather than obvious syntax.
- [ ] Output selection is easy to use.

# 33. Image-Reference Prompt Template

```text
Use the supplied reference image to create an OpenSCAD model.

Do not immediately approximate the object using arbitrary cubes and cylinders.

First:
1. Identify symmetry.
2. Identify the dominant construction method.
3. Extract useful geometric information such as silhouette, profile points,
   cross-sections, centerlines, feature ratios, and repeated patterns.
4. Choose a stable parametric representation.

For rotationally symmetric objects:
- Extract a radius-height profile.
- Use rotate_extrude().
- Add non-axisymmetric details afterward.

For extruded objects:
- Extract a 2D outline.
- Use linear_extrude().

For swept objects:
- Extract a path and cross-section.

For lofted objects:
- Extract several cross-sections.

After generating:
- Render a fixed orthographic view.
- Compare proportions to the reference.
- Return a structured critique.
- Modify only relevant parameters during the next iteration.
```

# 34. Final Design Principle

The central principle of this skill is:

> Good AI-generated CAD comes from finding the right geometric representation
> before generating the model.

The AI should not ask:

```text
Which cubes and cylinders resemble this object?
```

It should ask:

```text
What construction rule naturally defines this object?
```

Examples:

```text
rook            -> revolved profile + crown cuts
gear            -> involute gear library
bracket         -> 2D sketch + extrusion
bent tube       -> sweep
duct transition -> loft
gearbox         -> mechanism skeleton + housing
terrain         -> height map
statue          -> external mesh + mechanical OpenSCAD features
```

Once the representation is correct, OpenSCAD becomes substantially more
powerful, AI iteration becomes more stable, and the resulting CAD is easier to
understand, modify, manufacture, and reuse.
